# HSK Learning - project guide for Claude

Static GitHub Pages site that teaches Chinese grammar for the HSK (levels 3 to 7-9) to Dutch speakers.
Live: https://qunfong.github.io/HSK-Learning/ - deploys automatically from `main` (GitHub Pages, root folder, `.nojekyll`).
Sister project with the SAME code: https://github.com/Qunfong/Korean-Learning (TOPIK 1-6). See "Two repos, one codebase".

The owner communicates in Dutch. All site text is Dutch; Chinese only in examples and exercises.

## How it works
- No framework, no bundler, no dependencies. Plain HTML + one `assets/app.js` (vanilla JS, IIFE) + one `assets/style.css`.
- All pages are generated by `python tools/build_pages.py`. Never hand-edit `*.html` or `assets/data/*.js`.
- Progress lives only in the browser (`localStorage` key `hsk-learning-v1`: lessons passed, spaced-review rules, known words, last lesson, prefs). No backend.

```
assets/src/<level>/NN-slug.js   one lesson per file: a JS object literal wrapped in ( )
assets/src/<level>/_words.js    level word list ({ themes: [{ name, words: [[hanzi, pinyin, nl]] }] })
assets/src/<level>/_level.json  { level, dir }
assets/data/<level>.js          GENERATED: all lessons of a level merged (window.HSK.<key>)
assets/app.js                   all rendering: home, level, lesson, review, docs, word list/flashcards
assets/style.css                the whole design system
tools/site_config.py            site settings: V (cache version), brand, fonts/colours (SITE_HEAD), app settings (SITE_JS), levels
tools/build_pages.py            merges src -> data and writes every page (identical in both repos)
tools/validate.js               schema checker (identical in both repos)
tools/LESSON_SPEC.md            THE content spec for a lesson - read it before writing or changing lessons
```

Levels: keys `hsk3 hsk4 hsk5 hsk6 hsk79`, folders `hsk3 ... hsk7-9`. 15 lessons per level.

## Everyday commands
```bash
node tools/validate.js assets/src/hsk4/07-ji-you.js     # one lesson, full (deep) schema
node tools/validate.js assets/src/hsk4/*.js             # a whole level incl. _words.js
python tools/build_pages.py                             # merge + generate pages
node tools/validate.js assets/data/*.js                 # check the merged result
python -m http.server 8791                              # preview locally (pick a free port)
```
After ANY change in `assets/`, bump `V` in `tools/site_config.py` and rebuild, otherwise browsers keep the old file for up to 10 minutes (GitHub Pages `max-age=600`).

## Lesson content (summary - full rules in tools/LESSON_SPEC.md)
Order on the page: guess first -> the idea (problem, pattern blocks, rules, pitfall) -> examples -> nuance ("wanneer wel en niet", look-alike patterns, register) -> common mistakes -> 10 words -> dialogue -> reading text (+3 questions) -> 10-12 exercises (mc, fill, order, open) -> 3 review questions that come back later.
- Pedagogy comes from the Tutor and HSK Tutor skills: guess before teaching, distractors built from one real misconception, one idea per lesson, spaced review (first after 2 days, double when right, back to 1 day when wrong, learned at 16+ days).
- Writing: Dutch, short sentences, active voice, no idioms, no praise, NO em dashes (validator enforces).
- mc: correct option first (`answer: 0`); the app shuffles in a stable, per-question order.
- order: tokens in the correct order; joined without separator for Chinese. Other natural orders go in `alt`.
- Never claim official HSK 3.0 word-list membership or official exam items; content is AI-written practice and should be reviewed by a native speaker.

## Design system (why it looks like this)
Made with the `frontend-design` skill (claude-plugins-official). Brief: calm daily study, readable, clear where you are; the old look was judged old-fashioned and boring.
- Motif from the subject: the Chinese practice exercise book. The key character of a lesson sits in a 米字格 practice square (`.grid-char`); progress is a row of exercise-book squares (`.squares`); passing a lesson presses a red seal 过 (`.stamp`) - the ONLY animation (respects reduced motion).
- Colours (tokens in `:root`, dark mode via `prefers-color-scheme`): ink `#1c2230`, paper `#ffffff`, page `#f6f8f7`, exercise-book green `#2f6f5b` (primary/links/buttons), grid line `#cfe3d9`, seal red `#c0392b` (only seal, counts, errors).
- Type: Atkinson Hyperlegible for all Dutch/UI text; Noto Serif SC (Song style, like printed textbooks) for Chinese via `.zh` / `var(--zh)`. The `zh()` helper in app.js wraps Han characters automatically.
- Layout: content column ~70ch; lesson page = sticky numbered section nav on the left with scroll spy (horizontal chips on mobile < 980px); home = dashboard (continue, facts, levels as rows with squares).
- Navigation: sticky header with Leren, Herhalen (due count), Grammatica, Woorden and a "Ga verder" button (last opened lesson, or the next open one).
- Deliberately avoided (frontend-design "generic tells"): gradients as decoration, identical rounded cards with soft shadows, ALL-CAPS labels, "A · B" meta strings, "→" appended to links, cream + terracotta. Numbers only where the content is a real sequence (lesson sections, lesson list).
- Quality floor: responsive to 375px, visible keyboard focus, colour contrast, works without network fonts.

## Two repos, one codebase
`assets/app.js`, `assets/style.css`, `tools/build_pages.py`, `tools/validate.js`, `tools/LESSON_SPEC.md` are IDENTICAL in HSK-Learning and Korean-Learning. Change them in one repo, then copy to the other and rebuild both. Site differences live only in `tools/site_config.py`:
- `SITE_JS` sets `window.SITE` (language, TTS voice, romanization label, word separator for order questions, storage key, pass seal). Chinese values are the defaults in app.js.
- `SITE_HEAD` loads the fonts and overrides colour tokens (Korean: blue `#2b5a8a`, Noto Serif KR, seal 합).
- Optional app features switched on per site: `autoRom` (automatic romanization above Hangul, Korean only). Per level, `_level.json` may add `"noRom": true`; extra keys in `_level.json` are passed through to `window.HSK.<key>`.

## Working on content at scale
Big content jobs were done with parallel subagents: one agent per 5 lessons, each given LESSON_SPEC.md + the reference lesson `assets/src/hsk3/01-ba.js`, writing one file at a time and validating each file. Agents stall when asked to write very large files in one go - keep each Write to one lesson. After writing, run an "order question audit" pass (add natural `alt` orders, never stiff ones). Spot-check distractors yourself: a wrong option must be truly wrong.

## Testing notes
- Use the in-app browser for function checks via JS (complete a lesson programmatically, check `.stamp`, `#pcount`, `[data-continue]`).
- When the browser pane cannot screenshot (window hidden), use headless Edge from PowerShell: `msedge --headless=new --window-size=1280,1500 --screenshot=out.png URL`. Headless Edge does not render narrower than ~500px, so test mobile with the in-app browser's mobile preset instead.
- Deploy check: `gh api repos/Qunfong/HSK-Learning/pages/builds/latest` until `status` is `built`, then curl the live `app.js?v=N`.
